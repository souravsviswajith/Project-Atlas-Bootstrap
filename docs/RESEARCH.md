# Project Atlas research record

**Checked:** 2026-10-24 (UTC). Research is scoped to current installation/support constraints relevant to the catalog and preview design. A source link does not certify a provider implementation. Package identity, release, distribution support, architecture, and licensing must be checked again when a native adapter is developed.

| Area | Official source | Finding applied to Atlas | Remaining uncertainty |
| --- | --- | --- | --- |
| Node.js | [Node.js release schedule](https://nodejs.org/en/about/previous-releases) | Node distinguishes Current, Active LTS, Maintenance LTS, and EOL; the source listed v24 and v22 as LTS at the check date. The catalog uses an LTS selection policy instead of an unstable fixed “latest” version. | Package manager/Corepack availability varies by Node release and distribution. Must inspect actual Node build and project `packageManager` metadata. |
| Python | [Python Setup and Usage](https://docs.python.org/3/using/index.html) | Official docs cover per-platform setup, Windows installation-manager/version selection, virtual environments, and interpreter invocation. Catalog treats CPython, pip, venv, uv, and Conda as separate capabilities. | Python distribution, `py` launcher/manager, and package availability vary by OS and release. No Python detector/provider is implemented. |

WinGet is distributed with App Installer on supported Windows clients and has installer/source constraints. The registry separates the two shells. | WinGet may not be registered/available for a user yet; package source, interactive prompts, scope, and elevation require runtime detection/authorization. |

Version/vendor, `JAVA_HOME`, PATH, `java`, and `javac` must be verified together. | Vendor package availability and exact supported patch/architecture must be resolved at execution time. Maven/Gradle wrappers should override global defaults for projects. |
| Rust | [The Rustup Book — installation](https://rust-lang.github.io/rustup/installation/), [Windows toolchain notes](https://rust-lang.github.io/rustup/installation/windows.html) | rustup manages toolchains and installs tools under Cargo's bin directory; Windows MSVC targets require the Visual Studio linker/libraries. Inventory separates rustup from stable rustc/Cargo. | Exact linker/build prerequisites depend on target ABI and native dependencies. No Rust provisioning runtime exists in this repository. |
| Flutter / Dart | [Flutter install guide](https://docs.flutter.dev/install/manual), [add Flutter to PATH](https://docs.flutter.dev/install/add-to-path), [Flutter platform setup](https://docs.flutter.dev/platform-integration/windows/setup) | SDK channels and path setup are explicit; prerequisites and supported desktop targets vary by OS. `flutter doctor -v` is a diagnostic, not a generic repair command. | Docker | [Docker Engine install matrix](https://docs.docker.com/engine/install/) | Docker Engine/Desktop requirements differ by OS and Linux distribution; Windows/macOS Desktop and Linux daemon have distinct constraints. Android Studio install alone does not prove a usable SDK/emulator. | Device/emulator availability, SDK platforms/licenses, acceleration support, and Flutter diagnostics depend on the machine. |

## Design consequences

1. Capability metadata is descriptive. Provider package names are candidate identifiers, never automatically executed installer commands.
2. Version ranges and stable/LTS selection remain user intent; they are not silently rewritten to whatever a package feed currently labels latest.
3. Desired configuration and observed state are separate. A future runtime must resolve real platform/distro/architecture, executable paths, versions, environment variables, prerequisites, and verification output.
4. Package managers and shells are providers/contexts, not interchangeable commands. Windows PowerShell, Windows CMD, WSL Bash, Conda activation, containers, macOS shells, and Linux distributions need explicit execution contexts.
5. No installer, host detector, provider, or OS compatibility test has been executed as part of this repository work. The findings above are desk research only.
